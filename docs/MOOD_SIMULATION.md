# 手动排班心情模拟

计算在浏览器 Web Worker 内进行，不调用求解器或新增服务端 API。模拟读取当前手动排班、基建布局和干员练度；全员以 24 心情开始，跨班次和周期继承心情。每班开始重建排班位置，再先处理菲亚梅塔事件、后处理闲置入宿。

## 上游与规则维护

本功能经仓库使用者确认拥有复用授权后，移植自 [Rhodes-MoodSOC](https://github.com/ziyanQAQ/Rhodes-MoodSOC/tree/5204c840b7a99fdf79cd3815507894b001132162)，固定提交为 `5204c840b7a99fdf79cd3815507894b001132162`。计算口径遵循该版本的模型约定，包含原项目对挂件、阵营保护、技能叠加和闲置入宿的建模假设，不代表对游戏实测效果的额外保证。

- `src/mood-simulation/catalog.json`：上游技能子句、解锁和替换、阵营与变量规则的确定性导出。
- `rules.ts`：技能条件、变量、消耗/恢复账本。使用独立 Decimal 上下文（28 位、ROUND_HALF_UP）。
- `engine.ts`：跨班次积分、心情事件、入宿与布局快照；`presentation.ts` 使用事件右侧值查询时间点。
- 未覆盖的干员会明确报错；不会默认认为未知干员没有技能。新增游戏干员需要同步并验证规则目录。

开发时可用 Python 重新生成数据及对照样例；生产环境不需要 Python：

```text
python scripts/generate-mood-data.py /path/to/pinned/Rhodes-MoodSOC
python scripts/generate-mood-fixtures.py /path/to/pinned/Rhodes-MoodSOC
npm run test:mood-simulation
```

对照包含 3,131 组独立/组合速率案例和 18 组 1/3/7 周期轨迹，逐个检查上游事件节点和额外插值点，绝对误差小于 1e-6。Python 对照数据保留在测试文件中，不加入页面运行时依赖。事件计算保留上游按班次首次出现的干员顺序，以匹配 Decimal 最后精度位上的阈值先后关系。

## 配置边界

菲亚梅塔总开关及每班指定目标与排班共用。逐班启停、目标模式、等待回满、闲置入宿为模拟设置，单独保存在本地 `riic.manual-mood.v1`，不写入 MAA/Mower 导出。模拟快照不会改动排班。开始时间只影响时刻标签。

宿舍氛围默认等级上限；导入干员缺失练度时使用原模型默认精二、等级 30 并显示说明。已有干员练度优先，包括从闲置状态进入宿舍的干员。

## 待用户手动验收

- [ ] 打开 /manual，仅看到一套基建看板；切换「排班编辑 / 心情回放」，检查中英文、明暗主题和手机布局。
- [ ] 确认看板上方没有模拟标题、图标和副标题；周期数与播放控件在看板下方。下拉框使用共享 Combobox，列表、明细与设置弹窗使用全站滚动条，心情折线沿用 admin 的图表组件与样式。
- [ ] 编辑模式点击岗位仍能换人、排序、清空和设置自动补位；回放模式点击干员只切换曲线。开始播放或拖动时间轴自动进入回放，切回编辑会暂停且保留原排班。
- [ ] 将周期数改为 3 或 7，播放、暂停、拖动时间轴、回到起点；总长同步变化，跨周期心情连续。
- [ ] 点击模拟看板或干员列表，查看对应曲线、位置、当前心情和消耗/恢复明细。
- [ ] 修改菲亚梅塔指定目标，确认上方对应班次同步；自动目标、等待规则仅影响模拟。
- [ ] 模拟设置中的 Switch 可通过标签和键盘切换；闲置入宿使用 Accordion 展开，执行全选/全不选后重算仍保持展开。
- [ ] 桌面端「模拟设置」位于「配置 Box 与布局」右侧，弹窗最大宽度 960px；手机端从更多工具打开且不超出屏幕。草稿与 Box 信息保持单行，两种模式下均无额外操作提示。
- [ ] 查看后续班次的闲置入宿候选；关闭总开关或逐人参与，观察入住变化和事件说明。
- [ ] 模拟前后比较排班和 MAA/Mower 导出，确认仅显式修改的公共菲亚梅塔设置写入排班。
- [ ] 修改排班后立即操作其他配置，确认过期计算不会覆盖新结果；刷新后设置恢复。

受影响 UI：手动排班页面的编辑与回放共用一套看板；共享排班组件通过可选模拟展示参数显示实时心情和选中干员。
