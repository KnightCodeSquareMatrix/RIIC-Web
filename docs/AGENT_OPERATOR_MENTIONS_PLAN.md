# Agent 回复中的干员头像计划

## 目标与范围

在助理回复的干员名称左侧展示 18px 静态头像，使用现有干员目录与带版本号的本站图片。覆盖正文、标题、引用、列表和表格；跳过思考过程、工具输出、行内代码、代码块、链接文字及 URL。原始消息、历史存储、模型输入和服务端协议不变。

## 匹配与显示规则

1. 使用规范名称和已有的阿米娅职业名称别名；不做模糊匹配或自动猜测昵称。
2. 名称索引初始化一次，按最长名称优先消费文本，避免红云被拆成红。
3. 单字及双字名称保守识别：完整独立名称、明确强调/引用、或紧邻干员培养语境；英文名称要求词边界。不确定时保留文字。
4. 同一条 assistant 消息跨多个 text part 去重，以干员 ID 为准。每条消息最多 24 个头像，超限保留原文。
5. 图片与名字作为同一个行内单元；固定图片尺寸，避免加载造成占位变化。不增加按钮、边框或提示弹窗。
6. 图片失败保留名字；图片为装饰性内容，不重复屏幕阅读器读音，不改变复制出的文字。

## 流式与性能

- 未完成的 Markdown 块继续使用现有流式文字；块完成或 text part 完成后再识别。
- 解析和匹配为纯函数；名称使用前缀树，避免为每个名称重新扫描整段回复。
- 有界缓存复用已完成 text part 的解析/匹配结果；避免记录无限增长的流式快照。
- 静态图片使用 lazy loading、异步解码、本站版本化 URL；不使用 WebGL、外部图片代理、数据库或额外模型调用。
- 限制头像数量，并保持现有自动跟随滚动、减少动态效果和历史静态恢复行为。
- 根据后续补充要求，新出现头像在图片实际加载后播放 260ms 模糊淡入，仅影响 18px 图片区域；历史恢复与减少动态效果关闭动画。图片失败保留占位，避免错误回退造成换行变化。

## 实施步骤

1. 提取现有 Markdown 解析及行内分词为纯数据处理模块，保留当前格式行为；为块增加是否完整的信息。
2. 新增目录索引、保守匹配、消息内去重和缓存；把本站头像限定在目录映射中。
3. 接入 Markdown 渲染和 assistant text part 上下文；加入轻量行内头像及失败回退。
4. 添加纯数据处理测试及 Node + Playwright E2E，完成静态检查和局部长文本计时。
5. 交付本地 5174 预览入口、测试结果和用户手动验收清单。

## 验证与验收

- 名称：完整长名称、短名称、红云/红重叠、今年/空闲/夕阳等普通词、英文边界、阿米娅职业别名。
- 格式：强调、列表、表格、引用能识别；代码和链接不识别；文本内容与标点保留。
- 流式：名字分多个 chunk 到达、块完成后出现、跨工具气泡去重、减少动态效果、回复结束与历史恢复一致。
- 资源：目录外 URL 不可注入、头像失败不影响名称、固定尺寸与懒加载、24 个上限。
- 性能：长回复和重复名称的匹配计时；报告本机结果及其限制，不等同于生产性能承诺。
- 桌面/手机：不超出气泡及页面宽度，不干扰滚动、输入或选中文字。

## 已知限制与回退

纯文本无法百分之百判断同名普通词的语义，保守规则可能漏掉部分短名称。当前仅识别目录中文规范名和目录已有英文名；不自动翻译或推测昵称。稳定块增加头像仍可能发生一次换行调整，但图片下载不再改变占位。图片或匹配不可用时保留原文。移除前端渲染接入即可回退，无需数据迁移。
