# 森空岛数据能力矩阵

本项目当前锁定 `skland-kit 0.3.5`。用户同意当前条款与隐私政策并登录后，同一次玩家数据读取会通过 `snapshotsFromPlayerInfo` 同时生成两份公开 DTO：排班快照只包含求解所需字段，状态快照包含状态中心完整白名单。两份 DTO 都不会向浏览器转发上游原始响应，完整状态仍只停留在页面内存中。

上游类型来源：

- [客户端能力](https://github.com/AEtherside/skland-kit/blob/bbe0d470d4f00ce1f465c4c7d381000dc3335711/src/types/client.ts)
- [玩家资料](https://github.com/AEtherside/skland-kit/blob/bbe0d470d4f00ce1f465c4c7d381000dc3335711/src/types/player.ts)
- [干员字段](https://github.com/AEtherside/skland-kit/blob/bbe0d470d4f00ce1f465c4c7d381000dc3335711/src/types/character.ts)
- [基建字段](https://github.com/AEtherside/skland-kit/blob/bbe0d470d4f00ce1f465c4c7d381000dc3335711/src/types/building.ts)

| --- | --- | --- |

| 干员 | 职业、分支、星级、精英/等级、潜能、信赖、技能等级、S1–S3 专精、模组、当前皮肤、助战状态 | 当前不单独展示 |
| 已拥有皮肤 | 皮肤名、所属干员、品牌、获得时间、是否正在使用 | 当前不单独展示 |
| 基建 | 房间等级、进驻、心情、工作时长、生产/订单、库存、完成时间、宿舍氛围、线索、人力、训练、无人机、家具 | 概览、基建 |
| 公开招募 | 槽位开始与完成时间 | 概览 |
| 日周常 | 当前与总进度 | 概览 |
| 剿灭、保全、肉鸽 | 公开记录与奖励进度 | 当前不单独展示 |
| 活动、首领活动 | 关卡完成数量、活动时间、挑战记录 | 当前不单独展示 |

`operbox` 继续是传给求解器的最小干员子集。森空岛为不同职业形态返回不同 ID、相同求解器名称时，会归一化为一条并保留练度更高的记录。技能、皮肤、进度和完整基建快照不会进入 `infra-cli`，前端也不复制排班或效率求解逻辑。

完整状态的基建房间会保留训练室的训练位、协助位实时进驻、设施等级和 `0/2` 至 `2/2` 人数；这与顶部正在进行的训练任务概览相互独立。加工站由已识别布局补入完整状态，但当前上游类型不提供加工站实时进驻。训练室与加工站都会从精简排班快照中过滤，不参与当前班次匹配率、调整数或 MAA 房间比较。

## 已读取但明确排除

- 登录凭据、Cookie、扫码临时凭据、原始响应和上游内部 ID 映射。
- 活动宣传图、活动外链、干员/皮肤资产清单和基建气泡数据。
- 服务端路径、调试字段、请求正文及任何可用于还原会话的信息。
- 非 HTTPS 头像地址；头像展示使用 `no-referrer`。

## 本期不接入

- 签到状态和执行签到。上游客户端具备该能力，但本项目不会调用签到接口。
- 终末地、森空岛社区动态、仓库库存和上游未公开能力。
- 原始 JSON 数据转储。

## 会话与持久化

`skland-kit 0.3.5` 的玩家接口会一次返回组合数据。登录后，服务端分别生成最小排班快照和完整状态白名单；原始响应不会返回浏览器，完整状态快照只保留在页面内存，不写入浏览器持久化或服务端运行记录。

同一浏览器最多保留 5 个森空岛账号，每个账号使用独立加密 HttpOnly Cookie，并由加密索引 Cookie 记录当前账号。凭证从扫码成功起固定保存 7 天，刷新 token、读取会话或切换角色均不续期。PostgreSQL 只保存 HMAC 化的森空岛绑定标识、对应网站用户和授权时间，不保存 UID、昵称、Box 或令牌；最近授权满 7 天后绑定记录保留并标记为“待续期”，森空岛状态中心会要求重新扫码。浏览器 v5 持久化只保存布局、清理后的 Box、数据来源与最近排班；不得保存账号列表、UID、玩家资料、干员完整状态、进度、原始响应或森空岛凭据。“删除全部森空岛数据”按来源清除森空岛派生字段并解除全部绑定，同时保留独立导入的 MAA 数据和手动布局。
