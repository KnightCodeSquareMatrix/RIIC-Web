# Agent 界面与人格卡调研

## 本次落地

`/agent` 现在采用聊天产品常见的三层结构：桌面侧栏（新建对话、最近对话、在线状态）、消息主区（欢迎态建议、头像、工具状态卡）和固定底部 composer（多行输入、附件、停止生成、发送）。窄屏时侧栏自动隐藏，composer 使用安全区留白。

- 助理回复按 Markdown 展示：标题、粗体/斜体、链接、行内代码、代码块、引用、列表、表格和分隔线；链接只允许 `http`、`https`、`mailto`。
- 回复保留流式更新，不把工具调用混进正文；每个回复提供复制按钮。
- 图片、Markdown、TXT、JSON、PDF、CSV、XLSX 可以拖入或通过回形针按钮选择；单个附件限制 8 MB，一次最多 4 个。附件在发送前显示缩略图或文件卡片。
- 人格卡只保留服务端配置的可露希尔和用户上传两种入口（`.md`、`.txt`、`.json`）。上传内容保存在当前浏览器的 `localStorage`，下次打开页面优先恢复；每轮请求作为 `persona.content` 发送，服务端最多接收 36 KB，并在共享知识规则与工具守则之前加载。清除本地人格卡后恢复服务端可露希尔配置。

## 常见美化设计与取舍

调研中反复出现的有效模式是：

1. **欢迎态 + 建议问题**：新对话先给能力范围和 4 个可点击示例，降低空白输入压力。
2. **固定 composer**：输入框保持可见，Enter 发送、Shift+Enter 换行，附件按钮放在输入框旁边，停止生成与发送保持同一位置。
3. **流式消息稳定布局**：只让当前回答增长；自动滚动应在用户位于底部时触发，避免用户阅读历史时被拉回底部。
4. **Markdown 是内容层，不是装饰**：标题、列表、表格、代码块需要独立间距和可横向滚动；代码块应提供复制动作；不要用 `white-space: pre-wrap` 把所有内容当成一段文本。
5. **工具调用是状态卡**：显示“正在调用 / 完成 / 出错”和用户可理解的摘要，路径、内部错误和调试信息不暴露。
6. **模型/上下文选择放在输入附近**：人格、模型、知识库等会改变本轮行为的选项应当可见，并说明影响范围。

这些模式与 DeepSeek、ChatGPT 类产品的共同点是“内容居中、输入固定、空状态提供示例、回答使用 Markdown”。本项目保留了现有黑黄视觉语言，没有引入新的 UI 依赖。

## 人格卡的对外实现方法

### A. 会话级覆盖（当前实现）

浏览器把用户选中的预设或上传卡片放进本次 `/api/agent/chat` 请求的 `persona.content`。服务端截断长度后调用 `buildAgentSystemPrompt(personaContent)`。适合原型和私人使用：无需改表结构，也不会把角色卡写入服务器。

### B. 用户级人格（推荐的产品化方向）

增加 `agent_persona` 表（`id`、`user_id`、`name`、`content`、`visibility`、`created_at`、`updated_at`、`sha256`），配套：

- `GET /api/agent/personas`：只返回当前用户可见的元数据，不返回其他用户的私有卡片正文。
- `POST /api/agent/personas`：服务端校验扩展名、大小、字符集和 JSON schema，去除不可展示的元数据，存储正文或对象存储引用。
- `PATCH/DELETE /api/agent/personas/:id`：仅允许拥有者操作。
- `/api/agent/chat` 只接收 `personaId`，服务端按 `userId + personaId` 查询正文，避免客户端伪造他人的卡片。

### C. 公开人格市场

公开卡片必须额外有审核状态、举报、版本、作者和可见范围；默认以“风格层”加载，强制把站点工具规则、权限规则、事实来源放在角色卡之后。不要把上传卡片拼在最高优先级系统规则之后，也不要允许卡片修改工具白名单、计费、账号范围或安全策略。

### 对外端口的安全边界

- 上传端口必须要求登录和 CSRF / Same-Origin 校验，不能用未鉴权的“任意 URL 读取人格卡”。
- 限制正文大小、请求体大小、附件数量和总 token 预算；记录 hash、用户、时间和版本，便于撤销。
- 把人格卡当作不可信输入：它可以改变语气，但不能提升权限，不能覆盖站内规则，也不能让模型把卡片中的指令当成工具结果。
- 对公开分享使用只读快照或签名 ID，避免把本地文件路径、密钥或原始上传元数据暴露给其他用户。

## 图片与文件上传的功能考虑

1. **模型能力**：图片是否能被当前模型读取取决于 provider/model；页面会明确提示。DeepSeek/GLM 的文本模型并不等于视觉模型，服务端应在模型不支持 file part 时返回可理解错误。
2. **传输方式**：当前 AI SDK UIMessage 会把文件转成 data URL 随请求发送，适合小附件和原型；生产环境建议改为对象存储预签名上传，聊天消息只保存文件 ID、媒体类型和 hash。
3. **内容抽取**：PDF、XLSX、DOCX 不应直接假设模型能读。生产方案应先做 MIME 检测、病毒扫描、文本抽取 / OCR，再把抽取文本或检索引用交给模型；图片需要压缩、方向修正和 OCR 置信度。
4. **隐私与生命周期**：明确附件是否进入历史、保留多久、是否参与后续对话；默认按会话临时附件处理，过期清理对象存储。
5. **成本与体验**：上传前显示文件名、大小、缩略图、移除操作和失败原因；流式生成期间禁用重复提交，但保留停止；长文件显示“仅提取相关片段”或 token 估算。
6. **类型白名单**：扩展名不能作为唯一判断，服务端同时检查 MIME、magic bytes、解压大小和压缩炸弹；拒绝 HTML、脚本、可执行文件和未知类型。
