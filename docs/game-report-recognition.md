# 基建三日报表录入

`/account-health` 的报表区提供截图识别和手动填写。截图在浏览器 Canvas 解码；只把确认后的三天四项整数提交到 `/api/account/game-report`，图片本身不上传。单日报表识别到一个面板时提示用户提交三日报表。

五项依次为作战记录经验、贵金属价值、龙门币贸易、龙门币订单数量、合成玉。订单数量是贸易站龙门币行右侧的灰色数字，如 `PC-3-D.png` 第一天为 39。贵金属按游戏报表中的价值保存，不是赤金枚数。表格最右列为最新一天；最近一份记录按网站用户和当前森空岛角色读取，三日日均在前端计算，同时作为 `HealthDailyReport` 输入账号体检。旧的四项记录仍可读取，订单数量显示为空；新提交必须补齐三天订单数量。

## 识别口径

- 以黄色设施图标定位每个面板；完整截图按图标高度估计面板内部缩放。窄幅或裁剪图用三列间距估计，宽屏 PC 的面板间距与内部文字缩放比例不同，不能统一按列间距换算。
- 用行带与句尾探针区分作战记录、贵金属汇总行和贸易站的龙门币、合成玉行；青色笔画连通域与真实数字模板匹配。龙门币行右侧的灰色订单数量用独立窗口读取。
- 距离超过 `0.2`、字高小于 12 像素或未读到的数值留空；图片宽度低于 1400 像素或宽高比明显偏离完整截图时整张图改走手填。用户必须填满 3×4 表格才能保存。数字输入只接受 0 到 99,999,999 的整数。
- JPEG 压缩、裁剪图、数字粘连和不同游戏版式可能导致漏读或误读。JPEG 图整张转人工填写；上传后页面要求核对全部识别结果，不把识别视作最终确认。

`src/report-recognition/fixtures/` 是从真实样本裁切的测试夹具，仅保留报表指标所在的上半区，清除了下方干员姓名等个人内容。回归覆盖 1763 宽三日非零、三日全零、单日报表以及 2560 宽 PC 三日全零；仓库外的完整样本位于 `C:\Users\ray\Desktop\可露希尔\报表识别`。

另用 `mumu-3-al.png` 与 `模拟-3.png` 的上半区建立非零回归，覆盖额外的作战记录明细行和 2、3、7 易混字形。原始目录的两张压缩 JPEG 虽能定位三列面板，数字笔画仍不足以可靠自动填值，需人工核对。

交接文档列出的部分期望值与当前同名截图的可见数字不一致。例如当前 `模拟-3-zy.png` 第 2 天贵金属行显示 `46000`、合成玉行显示 `480`，而交接表写为 `146000`、`23310`。回归测试依据当前图片实际可见的数字；如样本被替换，应重新核对对应期望值。压缩 JPEG 和部分模拟器样本仍以人工修正为主。
