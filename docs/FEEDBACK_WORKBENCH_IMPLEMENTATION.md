# 反馈审阅与私有测试工作台

入口为 `/admin/issues`、`/admin/quality`。本文件记录实现和隔离验证，不代表生产发布已完成。

## 实现

- 新增已阅／忽略状态，打开详情不改状态，忽略必须写备注。单条及最多 100 条原子批量审阅保留操作者、时间、备注与历史；`expectedUpdatedAt` 冲突返回 HTTP 409 / `AIC-FEEDBACK-4003`。
- 服务端搜索分页，支持状态、设施、时间、错误码、求解器指纹；URL 保留筛选。独立详情面板提供当前页上一条／下一条、复现条件、历史及导出。
- 推荐按诊断编号、完整输入指纹、设施与相关干员／错误码匹配。干员来自问题房间和描述，统一目录名称、英文名及常用别名，不使用整个 box 聚类。人工关联／拆分保留历史，不改成员状态，拒绝链式归并。
- 管理员和审阅人共享审阅、导出、草稿、批次与结果。普通用户无权访问。用户权限管理和求解器同步仅限管理员。
- 版本 1 复现包兼容旧下载 JSON；纯 box 必须明确选择布局、轮换和菲亚梅塔参数。完整包不采用外部默认值，拒绝缺失条件和未知参数。独立草稿保留原始输入和不可变修订，复用干员编辑、布局、轮换和结果组件，不写个人工作区或云同步。
- 每批最多 500 用例，单文件 2 MiB，解压累计 100 MiB。JSON／ZIP 先暂存一小时；明确排除无效项后才生成草稿，服务端再次验证排除项。ZIP 检查路径、符号链接、压缩方式、边界、长度和 CRC，不解压到文件系统。
- 按完整输入去重并保留来源，批次固定一个或两个已验证 bundle。默认最新及上一生产版，只有一版时单版本执行。比较成功、有效性、收益、排班和耗时，耗时不自动判回归，结果不自动改状态。
- 私有数据库队列以 PostgreSQL advisory lock 限制并发为 1；每用例含两版本总计最多 10 分钟，顺序执行。支持取消、仅重跑失败项、中断恢复和不可变执行记录。
- 反馈派生数据不晚于来源到期，自主上传最多 30 天。读取时校验到期及来源，Worker 每分钟清理输入、结果、暂存预览、到期关联和孤立文件。

## 分阶段发布

1. 按仓库发布门禁准备经过审查的产物。先执行兼容迁移 `0016_private_feedback_quality.sql`，再部署私有 Worker，最后发布页面。迁移目前仅在隔离测试库执行。
2. `npm run worker:build` 输出两个独立 Worker。standalone staging 将 quality 产物复制到 `worker/quality-worker.cjs`；网页包不得包含 CLI、环境文件或私有数据。
3. 使用 `deploy/quality-worker.service` 和 `deploy/quality-private.env.example` 配置独立私有目录。网站与 Worker 必须使用相同私有根目录和业务数据库；不得复用生产求解队列、输入目录或旧 quality 存储。
4. unit 固定 CPU 2 核、内存 4 GiB、`KillMode=control-group` 和限定可写目录。Worker 没有公开端口，只能由后台启动。
5. 管理员请求同步后，Worker 从固定生产路径复制 CLI 和可选配套数据，验证 sidecar、文件清单、全部指纹、协议及 ping，成功后发布不可变 bundle。同步失败保留已验证版本并显示错误；首版不制造基线。
6. 发布后核对心跳、版本指纹、生成 box 的隔离计算，以及生产网站和生产 Worker 的健康、负载。隔离验证不能替代发布后的验收。
